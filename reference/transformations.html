Authoring guide / API reference

Write a transformation

Transformations are JavaScript function bodies that modify HTML before it is saved, previewed, or exported. Choose shared DOM mutations, a string replacement, or a handler invoked by HTML comments.

Transformations apply to the active HTML document. Use context.name when a transformation should only affect a particular document.

Quick start

  1. Open Transformations in the editor sidebar and add a transformation.
  2. Give it a name, choose Shared DOM, and set the stage to Preview + export.
  3. Paste the function body below into the code field. Do not add an enclosing function, script tag, or module export.
  4. With ready HTML, click Run once to inspect a temporary preview. This works even while the transformation is disabled.
  5. Enable it and choose Automatic to include it in subsequent previews and exports.
// Input: <a href="/offers" target="_blank">Offers</a>
document.querySelectorAll('a[target="_blank"]').forEach((link) => {
  const rel = new Set((link.getAttribute('rel') || '').split(/\s+/).filter(Boolean));
  rel.add('noopener');
  rel.add('noreferrer');
  link.setAttribute('rel', [...rel].join(' '));
});
// Output includes rel="noopener noreferrer". No return statement.

New transformations start disabled with Shared DOM input, Automatic trigger, and Export only stage. Review imported code before enabling it. Workers protect the editor from hanging when running slower operations; they are not a security boundary for untrusted JavaScript.

Stages & execution order

Stage selection controls persistence and when code runs.
Stage / value Automatic Manual / Run once Changes
Editor
editor		 After a source edit, at a safe line-change or blur boundary. Runs the selected transformation immediately against ready source, even if disabled. Editor source and saved HTML.
Preview + export
preview		 Each preview render and when preparing export. Run once adds the selected transformation to a temporary preview. Manual transforms are excluded from ordinary export. Output only; source stays intact.
Export only
export		 Every enabled transformation runs when Export opens. Trigger is ignored; Run once is disabled. Frozen export snapshot only.

Stages run in the order editor → preview → export. Within a stage, workspace list order applies; use the arrow buttons to reorder. Only enabled automatic editor and preview transforms participate in normal automatic runs. Enabling an automatic editor transformation schedules it for the next source edit; Run once applies it immediately.

For preview Run once, enabled automatic preview transforms run first. The selected transform is appended unless it is already in that automatic list; it is never run twice in that pipeline. Its temporary result lasts until the next render.

Export first handles pending automatic editor changes under the normal editing guards, then runs automatic preview transforms and enabled export-only transforms in one pipeline. A checkpoint after preview transforms refreshes both live previews; export-only mutations are excluded from that checkpoint. Copy and download use the same frozen export and do not rerun code.

Transforms run before CSS generation. Added utility classes generate CSS; utilities used only by removed elements disappear unless needed elsewhere or listed in the document's Additional classes. Document colors and inline CSS @apply are compiler features, not transformation context fields.

Shared DOM API

Input setting: Shared DOM · kind: "dom"

// Effective handler signature (the app supplies the wrapper):
async function handler(document, context) {
  // Your code goes here.
}
Parameter Contract
document The pipeline's mutable LinkeDOM document, not the editor UI document. Query elements, create nodes, update attributes, and move or remove content.
context Frozen object with the HTML document name and this transform's stage. See Context below.
Return value Must be undefined. Omit return or use a bare return;. Returning a node, string, null, or other value rejects the pipeline.

Consecutive DOM and comment transformations share exactly the same document object. Changes from earlier handlers are visible to later ones. You do not need to parse input or serialize output.

// Remove authoring-only elements. Suggested stage: Export only.
document.querySelectorAll('[editor-meta]').forEach((element) => {
  element.remove();
});

For fragment input, authored elements live in a synthetic document.body. Target the authored wrapper rather than expecting a real page body. For example, use document.querySelector('#content') when your fragment has that ID.

String API

Input setting: String · kind: "string"

// Effective handler signature:
async function handler(code, context) {
  // Must return a string containing the next HTML source.
}

code is the current HTML string, including changes made by previous transforms. Return the complete next string, not just a replacement fragment. An empty string is a valid string return. Missing returns and all non-string values reject the pipeline.

// Normalize curly double quotes in text and markup.
return code.replaceAll('\u201c', '"').replaceAll('\u201d', '"');

String replacement affects every matching occurrence, including scripts, styles, attributes, and comments. Prefer Shared DOM when the operation depends on HTML structure. A string transform does not get a document parameter.

Comment command API

Input setting: Comment command · kind: "comment". Set Command prefix to a bare name such as add-classes, without a colon.

<section>
  <!-- add-classes: rounded-lg p-4; -->
  <article>First card</article>
  Some text between cards
  <article>Second card</article>
</section>
// Effective handler signature:
async function handler(args, elements, document, context, comment, nodes) {
  // Mutate the DOM. Do not return a value.
}
Parameter Value
args String after the colon and before the first semicolon, trimmed at both ends. Internal whitespace stays intact. May be empty. No JSON parsing or argument splitting happens automatically.
elements Array snapshot of every following direct sibling element through the end of the comment's parent. It does not stop at another command. Descendants remain inside their sibling elements.
document Same shared document used by adjacent DOM transforms.
context Same frozen name/stage contract as other inputs.
comment The calling comment node. It is removed automatically after this invocation succeeds.
nodes Array snapshot of every following sibling node, including elements, text, and comments. Use it when preserving text and whitespace matters.

Example: add utility classes

const classes = args.split(/\s+/).filter(Boolean);
for (const element of elements) {
  element.classList.add(...classes);
}

With the input above, both articles get class="rounded-lg p-4", the text stays in place, and the calling comment is consumed in the transformed output.

Matching rules

  • Prefixes are case-sensitive and must match ^[a-zA-Z_][\w-]*$: an ASCII letter or underscore, then letters, digits, underscores, or hyphens.
  • Comment contents must match ^\s*([a-zA-Z_][\w-]*)\s*:([^;]*);\s*$. Whitespace around the prefix, colon, and entire command is allowed.
  • The semicolon is required. Arguments cannot contain a semicolon, even inside quotes. Non-whitespace after it prevents a match.
  • Unknown prefixes and malformed calling comments stay untouched. An invalid configured prefix fails the transform even when no comment matches.

Lifecycle and ordering

Matching comments are collected in document order at the start of each handler pass. Each connected comment with a parent element runs once. Its sibling arrays are captured immediately before invocation, so earlier mutations affect later calls. Moving a node does not disrupt iteration of an existing array. Detached comments are skipped. Newly inserted command comments wait for a later handler pass.

Commands always run automatically and have no Run once button. Allowed stages are Editor and Preview + export. Editor commands consume comments in saved source under the usual editing guards. Preview commands keep calling comments in source and consume them in each output. Imported manual commands normalize to automatic; export-stage commands normalize to preview. When two handlers use the same prefix, the first normally consumes the comments before the second can see them.

If any invocation throws or returns a value, the worker rejects the whole pipeline, including earlier mutations and comment removal.

Context & async code

Field App-supplied value
context.name Active HTML document's name. This is not the transformation name or ID.
context.stage "editor", "preview", or "export", from the transformation's target. A preview transform still sees "preview" during export.

The app passes no palette, settings, source URL, selected elements, file ID, or UI objects. Context is frozen with Object.freeze; assigning its properties in the strict-mode handler throws. Do not use it to store state.

// Shared DOM: restrict a workspace-wide transform to one document.
if (context.name !== 'About us') return;
document.querySelectorAll('[data-company-address]').forEach((element) => {
  element.textContent = '42 Wallaby Way';
});

All three inputs support top-level await because the app compiles the body as an async function. Return an awaited string in String mode; return nothing in DOM or comment mode. Network requests, if used, follow browser worker and CORS rules and consume the same execution budget.

// String mode: minimal async example, with no external dependency.
const html = await Promise.resolve(code);
return html.replaceAll('[[document-name]]', context.name);

Each pipeline gets a fresh worker. Variables and worker globals do not persist between renders. Within one DOM pipeline you can attach temporary properties to document or nodes, but those properties disappear if a string boundary causes reparsing.

Example recipes

Remove empty class attributes

Shared DOM · Editor · Automatic. This changes saved source; editing guards may defer it until the cursor leaves the affected region or the editor blurs.

document.querySelectorAll('[class]').forEach((element) => {
  if (!element.getAttribute('class').trim()) {
    element.removeAttribute('class');
  }
});
// <p class=" ">Hello</p> becomes <p>Hello</p>.

Replace an authoring marker with themed markup

Shared DOM · Preview + export · Automatic. Use node APIs for text instead of interpolating it into HTML.

document.querySelectorAll('[data-callout]').forEach((element) => {
  const label = document.createElement('strong');
  label.className = 'text-accent';
  label.textContent = element.getAttribute('data-callout');
  element.prepend(label, document.createTextNode(' '));
  element.classList.add('rounded-lg', 'bg-surface', 'p-4');
  element.removeAttribute('data-callout');
});
// Input: <aside data-callout="Tip:">Book online.</aside>
// Output: a styled aside beginning with <strong>Tip:</strong>.

Wrap heading sections while preserving text

Comment command · prefix sections · Preview + export. Call with <!-- sections: h2; --> before sibling headings and content. Arguments are a CSS selector; an invalid selector rejects the pipeline.

const parent = comment.parentElement;
let wrapper;
for (const node of nodes) {
  if (node.nodeType === 1 && node.matches(args)) {
    if (wrapper) wrapper.append(document.createTextNode('\n'));
    wrapper = document.createElement('section');
    wrapper.className = 'mb-8';
    wrapper.append(document.createTextNode('\n'));
    parent.insertBefore(wrapper, node);
  }
  if (wrapper) wrapper.append(node);
}
if (wrapper) wrapper.append(document.createTextNode('\n'));

Content before the first matching heading remains outside the wrappers. Each matching heading starts a new section containing that heading and all following sibling nodes until the next match or the end of the parent.

Keep automatic source edits repeatable

Automatic transforms may run repeatedly. Prefer operations that settle after one application: adding an existing class, setting an attribute, or removing a marker. Unconditionally appending a badge in an Editor transform will duplicate it on later edits; check for an existing badge or consume a marker.

JSON import & fields

Transformation import expects a top-level JSON array, not a workspace backup or an object containing a transformations property. Export transformations downloads transformations.json. Import appends records, assigns fresh IDs, preserves array order, and disables all imported transforms regardless of their enabled fields. Restoring a workspace backup also disables imported code; ordinary saved-workspace reloads preserve enabled state.

[
  {
    "name": "Remove editor metadata",
    "kind": "dom",
    "target": "export",
    "mode": "auto",
    "enabled": false,
    "code": "document.querySelectorAll('[editor-meta]').forEach(element => element.remove());"
  },
  {
    "name": "Add classes from comments",
    "kind": "comment",
    "command": "add-classes",
    "target": "preview",
    "mode": "auto",
    "enabled": false,
    "code": "const classes = args.split(/\\s+/).filter(Boolean); for (const element of elements) element.classList.add(...classes);"
  }
]

JSON strings require escaping: a JavaScript \s in the code field becomes \\s in JSON, newlines become \n, and double quotes become \". The in-app code field accepts plain JavaScript without JSON escaping.

Validation and normalization in validateTransformations.
Field Type / values Import behavior
name Required string Preserved as given; empty strings are accepted.
code Required string Function body. Syntax and return contracts are checked at execution, not import.
id String Optional for imports; replaced by a UUID. Internal loading with preserveIds retains a nonempty ID and rejects duplicates.
kind dom, string, comment Missing or unrecognized values become string.
target editor, preview, export For DOM/string, missing or unrecognized values become editor. For comments, only editor stays editor; everything else becomes preview.
mode auto, manual Only exact auto stays auto; other values become manual. Comments always become auto. Export ignores mode.
enabled Boolean Validator accepts only literal true as enabled; import/restore then forces false.
command Comment prefix string Only retained for comment input. Converted to a string and trimmed; prefix validity is checked at runtime.

Unknown fields are dropped by validation. Specify kind, target, and mode explicitly when sharing transforms; legacy defaults differ from the defaults for adding one in the UI.

Runtime & serialization

  • Code executes in a module Web Worker using LinkeDOM 0.18.9. Handlers are strict-mode async functions. Static module imports do not belong in a function body.
  • The supplied DOM supports queries and mutations, not rendering. There is no editor window, Monaco instance, layout engine, or reliable browser layout measurement. Authored scripts do not execute as part of DOM transformation parsing.
  • DOM parsing is lazy. String-only transforms operate on strings. The worker still loads its LinkeDOM module dependency before it signals ready.
  • At a DOM → string boundary, the document is serialized. At the next string → DOM boundary, HTML is parsed again. Group DOM/comment transforms together to preserve node identity and avoid extra work.
  • The worker treats source matching /<!doctype\s|<html[\s>]/i as a full document. Other input goes into a synthetic body's innerHTML.
  • Full documents serialize with document.toString(). Fragments serialize as document.head.innerHTML + document.body.innerHTML, without synthetic document wrappers.

DOM round trips can normalize markup and quoting; they do not promise byte-for-byte source preservation. Put intended fragment output inside its authored wrapper rather than modifying synthetic html/body attributes, which are omitted during fragment serialization.

The export checkpoint serializes the document but keeps the object alive, so adjacent preview and export DOM handlers share node identity. Separate editor and preview pipelines do not share a document or worker.

Readiness, limits & errors

The source must be HTML ready before automatic transforms, Run once, or export. Unfinished quotes, attributes, comments, and required closing tags pause transformations. This is an editing-readiness check, not full HTML conformance or accessibility validation. Fragments, void elements, optional end tags, custom elements/attributes, and SVG are supported.

Unfinished source still saves. Automatic preview transforms resume when source is ready. Automatic editor transforms wait for a line change or blur while focused, and protect selected lines plus the entire opening tag surrounding a selection. A conservative change range may defer distant edits until blur. Text composition also pauses execution. Results from stale asynchronous runs cannot overwrite newer typing.

Automatic source edits track selections through preceding edits and preserve scroll. Manual transforms restore the same line and column, clamped to the new content; the plain-text fallback restores character offsets.

Failure What happens / what to check
Wrong return type DOM/comment: remove the return value. String: return the complete string.
Thrown error or invalid JavaScript The entire worker pipeline rejects; no partial HTML is applied. Error messages identify the transformation name.
Unsafe/incomplete output The controller checks final pipeline output and the export preview checkpoint. Invalid output cannot replace source or preview.
Three-second execution limit A single budget covers the whole pipeline, including awaits, parsing, serialization, and handlers. The worker is terminated; reduce work or avoid slow requests.
Dependency load failure The worker has a separate 15-second startup limit. Serve over HTTP and check the connection to the pinned CDN.
No visible change Check enabled state, stage, trigger, selector, command spelling/semicolon, ready status, and pending editor boundaries. Export-only changes appear after Export opens.

The last successful preview remains on failure. Success logs show the transformation name and elapsed milliseconds; a comment transform produces one log for its entire pass, even with no matches. Errors and notifications appear inline in the editor status area.

Rollback covers returned HTML, not external side effects such as a network request. Run only trusted code and do not use transformations as HTML sanitization for untrusted JavaScript. Scripts in transformed authored HTML may subsequently run in the sandboxed live preview.

Pipeline service API

For application code and debugging, the local ES module exports this lower-level function. Normal transformation authors only need the function-body APIs above.

import { runTransformations } from '../app/Services/Transformations.js';

const result = await runTransformations(
  '<p>Before</p>',
  [{
    name: 'Rename text',
    kind: 'dom',
    target: 'preview',
    code: 'document.querySelector("p").textContent = "After";'
  }],
  { name: 'Example', stage: 'preview' },
  1
);
// result.code: '<p>After</p>'
// result.checkpoint: '<p>After</p>'
// result.logs: ['Rename text: … ms']

runTransformations(code, transformations, context = {}, checkpointAfter = null) returns a Promise resolving to { code, logs, checkpoint }, or rejects with an Error. Paths in the example are relative to a module in this reference folder.

  • code: input HTML string.
  • transformations: already-selected ordered records. This service does not filter enabled flags, mode, or stages and does not normalize imported records.
  • context: structured-cloneable values copied to the worker. Each handler receives a shallow frozen copy with stage set to transform.target || context.stage.
  • checkpointAfter: number of completed transforms after which to serialize a snapshot. Zero captures the original input; the default null captures none.
  • code in the result: final serialized HTML. logs: one timing string per transform. checkpoint: captured HTML or undefined when no checkpoint was reached.

With no transforms, it resolves immediately with unchanged code, empty logs, and checkpoint equal to the input. Each nonempty call creates and terminates a new worker. The service does not perform HTML readiness validation, editing guards, compilation, persistence, or stale-result rejection; the editor controller supplies those behaviors.
