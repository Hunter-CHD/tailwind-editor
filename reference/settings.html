Configuration / Usage reference

Editor & document settings

Use workspace preferences to make editing comfortable, and document settings to control how each HTML document renders and exports. This guide explains the controls, defaults, saved fields, and practical effects.

Which settings apply where?

Where to open Scope Controls
Header → Settings Workspace-wide editor preferences Editor font size, long-line wrapping, workspace backup and restore.
Header → Themes Workspace appearance Paper, Midnight, Sand, and a custom editor palette.
Document toolbar → gear Active document only Preflight, Tailwind base size, additional classes, and document colors.

Workspace appearance changes the interface and Monaco. Document settings affect the inline preview, synchronized popout, and generated export for that document. Each document keeps its own rendering settings when you switch files or change the editor theme.

Editor preferences

Open Settings, adjust these fields, and click Save settings. Closing the dialog without saving leaves the form changes unapplied.

Control / saved field Default Behavior
Editor font size
settings.fontSize		 14px Allowed range: 11–24px. Changes source editor text size, including the plain-text fallback. Does not change authored HTML or preview text size.
Wrap long lines
settings.wordWrap		 true Visually wraps source lines to the editor width without inserting line breaks into HTML. Applies to Monaco and the fallback editor.
Documents sidebar toggle
settings.sidebarCollapsed		 false The toolbar toggle hides or shows Documents, including on mobile. Saves immediately as a workspace preference.

Alt + Z toggles wrapping immediately while editing or while Workspace settings is open. The shortcut is ignored while another dialog is open. Imported workspace preferences clamp font size to 11–24, default wrapping to enabled unless explicitly false, and collapse the sidebar only for literal true.

Editor themes

Open Themes to select Paper, Midnight, Sand, or your saved custom theme. Theme selection applies and saves immediately. Custom colors are applied together when you submit Save custom theme.

A custom theme has four opaque six-digit hex colors: background, surface, text, and accent. Swatches open the color picker; the fields also accept direct hex entry. Light/dark color scheme is derived from surface brightness.

New and imported HTML documents copy these four colors from the current editor theme. Existing documents retain their palettes. To copy a new theme into an existing document, use Document settings → Import editor theme → Save settings.

Editor font size controls the source editor. Editor theme controls interface appearance. Document colors and Tailwind base size control generated document styling. These settings serve separate purposes.

Document settings

  1. Select the HTML document you want to configure.
  2. Click the gear beside its name. The dialog shows which document you are editing.
  3. Adjust Preflight, base size, additional classes, and the palette.
  4. Click Save settings to validate and apply all fields together.

Invalid palette JSON, invalid color names/values, or an invalid base size keeps the dialog open and reports an inline error. Fix the values and save again. Import editor theme fills the palette form; it does not apply changes until you save.

Saved document field Type / default Purpose
preflight Boolean / true Include generated Tailwind base styles.
tailwindBaseSize Number or null / null Optional fixed pixel basis for rem values in generated utility declarations.
safelist String / empty Additional space-separated utility classes to generate.
colors Object / copy of editor theme colors Named colors available to this document's utilities and @apply.

These are metadata fields alongside the HTML source in workspace backups. A plain HTML import starts with new document defaults; it does not restore settings from a workspace backup. Document duplication preserves document settings.

Include Tailwind base styles (Preflight)

Enabled by default. Preflight provides generated base/reset styling alongside utility CSS. Turn it off when the destination site already provides base styles and you want fewer reset interactions.

Disabling Preflight keeps authored styles and utility generation. Preview frames also apply a separate html, body { margin: 0; padding: 0; } baseline, which authored styles can override. That preview-only baseline is excluded from export.

Fragment exports scope generated CSS to the detected authored wrapper. Generated html/body Preflight rules are omitted unless the wrapper is an authored html/body element or the input is a full document. Generated scoped styles target descendants; use authored CSS to style the fragment wrapper itself. External stylesheets and authored styles keep their own scope.

Override Tailwind base size

Off by default, saved as null. With no override, generated rem values use the page's normal root font size. Enable the checkbox to set a fixed pixel basis for rem values in generated Tailwind utility declarations, including expanded @apply.

The field initially shows 16px. Valid values are finite numbers of at least 0.01px; decimals are allowed. Turning the override off saves null, regardless of the disabled field's displayed value.

<div class="p-4 text-base">Example</div>
// Standard utility values: padding: 1rem; font-size: 1rem.
// Base size 16: those generated lengths resolve to 16px.
// Base size 20: those generated lengths resolve to 20px.

This helps keep embedded utility sizes consistent when a host site uses a different root font size. Internally, generated rem declaration values use calc(amount * var(--twe-rem)) with a generated base variable. The override does not change handwritten rem CSS, inherited text sizes, or the host root font size. Selectors and media conditions are outside this conversion, so it does not rescale responsive breakpoints.

Additional classes

Enter space-separated utility names in Additional classes, saved as safelist. The compiler generates utilities found in HTML automatically, but does not execute authored scripts to discover runtime class names.

hidden block bg-accent hover:bg-accent/80 md:grid

For example, if a script changes an element from hidden to block, list block here when it is absent from static markup. This generates its CSS without adding the class to any element or changing script behavior. Variants and document color utilities work here too.

Classes inserted directly into HTML by a transformation are visible to the subsequent compiler. Add classes here for later runtime changes or other cases where the final transformed markup does not contain them. Removing unused entries allows their CSS to disappear when nothing else uses them.

Document colors

The palette is a JSON object mapping lowercase names to opaque six-digit hex colors. New documents copy the current editor theme's four colors; you can add additional names or replace the palette.

{
  "background": "#f5f6f8",
  "surface": "#ffffff",
  "text": "#202b36",
  "accent": "#0f766e",
  "brand-secondary": "#1d4ed8"
}

Names match ^[a-z][a-z0-9-]*$: start with a lowercase letter, then use lowercase letters, digits, or hyphens. Values must be strings such as "#0f766e". Short hex, alpha hex, rgb(), named CSS colors, arrays, and comments in JSON are unsupported. An empty object is valid, but removes these custom color names.

<main class="bg-background text-text">
  <article class="bg-surface border border-accent">
    <a class="text-brand-secondary hover:text-accent/80" href="/offers">
      View offers
    </a>
  </article>
</main>

Default Tailwind colors remain available. Opacity is expressed through utility suffixes such as /80, while saved color values stay opaque. Document colors work in utilities, Additional classes, and inline CSS @apply; they do not automatically replace arbitrary handwritten CSS or create a general-purpose palette API for transformations.

Import editor theme replaces the palette form with the current four editor colors, including removing extra custom names from that form. Save settings to apply the replacement, or close the dialog to discard it.

Saving & backups

Saved preferences and document metadata persist in the browser's IndexedDB for this origin. Reloading retains them; clearing browser storage can remove them. Hosting on a different origin starts a separate workspace. Files remain browser data until you explicitly download them.

Settings → Download backup downloads tailwind-workspace.json with documents, folders, document colors/settings, transformations, and workspace preferences. Restore backup validates a JSON backup and asks before replacing the current workspace. Restored JavaScript transformations are disabled for review.

An exported HTML file contains generated styling, not a restorable workspace settings bundle. Keep a JSON backup to preserve editable workspace configuration. The settings dialog's size summary estimates serialized workspace data; it is not an available-storage quota.

Configuration examples

Embed a fragment on a client's site

  1. Open the fragment's Document settings and consider disabling Preflight if the host already supplies reset styles.
  2. Enable Tailwind base size at 16px when generated rem lengths should remain independent of the host's root font size.
  3. Save a document palette matching the client's brand and use named utilities in the fragment.
  4. List classes added only by runtime scripts in Additional classes.
  5. Save settings, inspect the preview, and export. Check the result in its destination because host inheritance and surrounding CSS still matter.

Change editor appearance while retaining document branding

Choose Midnight under Themes. Existing documents keep their current palettes. New HTML documents copy Midnight's colors. To adopt Midnight's colors in an existing document, open its gear dialog, click Import editor theme, then Save settings.
